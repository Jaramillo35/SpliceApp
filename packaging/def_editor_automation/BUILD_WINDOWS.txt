DEF Editor Automation - Terminal Material updater
=================================================

What it is
----------
Sets the Term Matl of circuits in DEF EDITOR from an Excel list.

You navigate DEF Editor by hand to Edit Harness > Circuits. Then, in this
window: Connect (pick the DEF Editor window), Choose Excel, Preview, Apply.

The Excel has three columns in its first row - CNUM, Circuit Name, Terminal.
Terminal is Silver, Gold or Tin (any case) or empty. Each row is matched to
the circuits grid: CNUM to "Connector No", Circuit Name to "Circuit". The
matching row's Term Matl cell is opened and the value picked from DEF
Editor's own list (BERYLLIUM, GOLD, SILVER, SILVER+NICKEL, SILVER+TIN, TIN).

Preview first, always. Every row is shown with what would happen and nothing
is touched: Will change (with the current value) / Already that value /
Not in the grid / Terminal empty - left as is / Unknown value - left as is.
Apply sets exactly the rows marked "Will change", one at a time, reads each
cell back, and reports Applied or Failed per row. "Export results CSV" keeps
the record. Nothing is guessed: any Terminal other than Silver, Gold or Tin
is reported and left alone.

The navigation test from the earlier build is still in the kit
(python main.py --selftest runs it, and the updater, against the demo).

No customer, user, machine or business data is present anywhere in this kit.
The programme the demo serves is invented.


Try it first (any machine, no DEF Editor, no install)
-----------------------------------------------------
   python main.py --selftest      run the whole test and print the result
   python main.py --demo          open the window attached to the demo

Only "Connect to DEF Editor" needs Windows and pywinauto. Everything else -
the demo, the selftest, the tests - runs anywhere, which is how the sequence
was proven before it ever met the real application.


Build the exe (one time, on a Windows 10/11 PC with Python 3.11+)
-----------------------------------------------------------------
1. Unzip this folder anywhere, e.g. C:\DEFEditorAutomation

2. Open a command prompt in that folder and install dependencies:

      pip install -r requirements.txt

3. Build:

      pyinstaller def_editor_automation.spec

4. The exe is at:

      dist\DEFEditorAutomation.exe

   Copy it anywhere. Whoever runs it does NOT need Python.


Use
---
1. Start DEF Editor, sign in, and open the harness: Edit Harness > Circuits,
   so the circuits grid with the Term Matl column is on screen.
2. Run the exe, press "Connect to DEF Editor". A picker lists EVERY window on
   the desktop; the ones that look like DEF Editor are first and marked.
   Double-click the right one. The kit never guesses the window title.
3. "Choose Excel..." - the update list. The label says how many rows it read,
   or what is wrong with the file (a missing column is named).
4. "Preview". The table fills, one line per Excel row, coloured by what will
   happen. Read it. Rows marked "Not in the grid" or "Unknown value" are
   yours to fix in the Excel; nothing will be done to them.
5. "Apply N change(s)". Rows turn Applied (green) or Failed (red) one by one;
   a Failed row says what the cell read back. "Export results CSV" saves the
   table next to the exe.

If Preview reports that the grid has no "Connector No" / "Circuit" / "Term
Matl" column, DEF Editor is not on the Circuits page, or the columns are
named differently in your release - the names live in defauto\ids.py
(TERM_COLUMNS). If Apply fails on every row, the cell editor is not what the
kit assumed: take a RECORD STRUCTURE snapshot with the grid on screen and
send the structure folder.


Recording the structure (do this first when something fails)
-----------------------------------------------------------
The automation was written from a description of DEF Editor's controls, not
from its UI Automation tree. When a step reads the wrong thing - the Vehicle
field offering "Phase" and "Close" - the tree is what shows why.

1. Attach to DEF Editor.
2. In RECORD STRUCTURE, type a label ("composite page"), press "Snapshot now".
3. Tick "Auto: snapshot whenever the window changes", then navigate DEF
   Editor by hand exactly as you want it automated - each change is saved.
4. Untick Auto. The "structure" folder next to the exe holds one JSON per
   snapshot and an index.md. Push that folder to the repository.

What is recorded: every element's control type, AutomationId, class name,
position, enabled/visible, and the tree. Names are kept only for interface
controls (buttons, menus, tabs, headers, windows). For anything that carries
data - grid cells, edits, list items, labels - only the SHAPE of the text is
kept ("3 upper/digit"), never the text. Grids record their headers and row
count and descend into two rows for shape. Leave "Redact values" on.

Changing what it filters for
----------------------------
B4 is one constant, at the top of defauto\workflow.py:

      TARGET_CIRCUIT = "B4"

or type it in the window's "Circuit to filter" field, or pass it on the
command line:  python main.py --selftest --circuit A0


When DEF Editor changes
-----------------------
Every AutomationId lives in defauto\ids.py and nowhere else. If step 1 reports
something missing, find the new id (Inspect.exe, or Accessibility Insights for
Windows), change it in that one file, and everything above it keeps working.


How it is laid out
------------------
   main.py                entry point (window / --demo / --selftest)
   defauto\workflow.py    THE TEST - the ten steps, and nothing else
   defauto\gui.py         the window: four fields, one button, ten steps
   defauto\ids.py         every AutomationId - the contract with DEF Editor
   defauto\backend.py     the seam: UiaBackend (pywinauto) and the protocol
   defauto\fake.py        the scripted DEF Editor used by Demo and the tests

   defauto\navigation.py  menu navigation, and nothing else
   defauto\composite.py   program / model year / phase / composite / harness
   defauto\harness.py     the harness page
   defauto\circuits.py    the Circuits page
   defauto\gridreader.py  reading a DataGridView, and exporting one
   defauto\reports.py     writing files

   defauto\devices.py       \
   defauto\splices.py        |  present and tested, but NOT used by this
   defauto\complexity.py     |  test. They cover the other DEF Editor pages
   defauto\qualitychecks.py /   from the original specification.


Notes and limits
----------------
- Attaching needs DEF Editor already running and signed in. This kit never
  handles credentials and never automates a login.
- It only reads. Nothing in this sequence edits, saves or signs anything off.
- Screen coordinates are never used - everything is found by AutomationId.
- One thing this kit cannot know without standing in front of DEF Editor:
  whether the circuit filter box matches the Circuit column or anywhere in
  the row (a sales code of ZB4 contains B4). Step 10 reports the row count
  AND how many rows have Circuit exactly equal to the target, so the run
  tells you which it turned out to be.
