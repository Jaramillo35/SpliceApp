DEF Editor Automation - Windows build steps
===========================================

What it is
----------
A prototype for automating DEF EDITOR through Windows UI Automation. It opens
a workbench window that attaches to a running DEF Editor, walks the normal
sequence (program > model year > phase > composite > harness), reads any
module's grid, runs the quality checks, and exports what it read as CSV.

It is built so it can be developed and proven WITHOUT DEF Editor. Every
workflow runs against a scripted stand-in, so the automation logic is
exercised before it ever meets the real application - press "Demo mode" in
the window, or run the selftest below.

No customer, user, machine or business data is present anywhere in this kit.
The programme the demo serves is invented.


Try it first (any machine, no DEF Editor, no install)
-----------------------------------------------------
   python main.py --selftest      runs a whole workflow and prints the result
   python main.py --demo          opens the window attached to the demo

Only "Connect to DEF Editor" needs Windows and pywinauto.


Build the exe (one time, on a Windows 10/11 PC with Python 3.11+)
-----------------------------------------------------------------
1. Unzip this folder anywhere, e.g. C:\DEFEditorAutomation

2. Open a command prompt in that folder and install dependencies:

      pip install -r requirements.txt

3. Build:

      pyinstaller def_editor_automation.spec

4. The exe is at:

      dist\DEFEditorAutomation.exe

   Copy it anywhere. Whoever runs it does NOT need Python.


Use
---
1. Start DEF Editor and sign in as usual.
2. Run the exe, then press "Connect to DEF Editor".
3. Press "Diagnose" FIRST. It reports which of the AutomationIds this kit
   depends on are present in the window it attached to. If any are missing,
   DEF Editor has changed and the fix is one file - see below.
4. Pick program / model year / phase, press Filter, pick a composite and a
   harness, then "Open harness".
5. Choose a module on the left. The grid is read live; the Filter box and the
   checkboxes are the application's own, so what you see is what an engineer
   at the screen would see.
6. "Export this grid" writes a timestamped CSV into the exports folder
   ("Choose folder..." changes where).


When DEF Editor changes
-----------------------
Every AutomationId lives in defauto\ids.py and nowhere else. If Diagnose
reports something missing, find the new id (Inspect.exe, or Accessibility
Insights for Windows), change it in that one file, and everything above it
keeps working. That is the whole reason the ids are not scattered through the
code.


How it is laid out
------------------
   main.py                entry point (window / --demo / --selftest)
   defauto\ids.py         every AutomationId - the contract with DEF Editor
   defauto\backend.py     the seam: UiaBackend (pywinauto) and the protocol
   defauto\fake.py        the scripted DEF Editor used by Demo and the tests
   defauto\navigation.py  menu navigation, and nothing else
   defauto\composite.py   steps 1-2: programme, composite, harness
   defauto\harness.py     step 3: the harness page
   defauto\devices.py     \
   defauto\circuits.py     |
   defauto\splices.py      |- one module per DEF Editor page
   defauto\complexity.py   |
   defauto\qualitychecks.py/
   defauto\gridreader.py  reading a DataGridView, and exporting one
   defauto\reports.py     writing files
   defauto\gui.py         the workbench window

The layers are kept apart on purpose - navigation, grid reading, validation
and reporting each know one job - so a change in how DEF Editor is navigated
cannot break how a grid is exported.


Notes and limits
----------------
- Attaching needs DEF Editor already running and signed in. This kit never
  handles credentials and never automates a login.
- The inline sign-off refuses to press the button while any pair is still
  failing. Passing bypass=True sets the application's OWN bypass checkbox, so
  a bypassed sign-off looks in DEF Editor exactly like one a person made -
  there is no path here that signs off invisibly.
- Screen coordinates are never used. Everything is found by AutomationId,
  except the three inline action buttons, which have none and are found by
  their visible text.
- Run it against a harness you are willing to have read. It only reads and
  runs the application's own checks, but it is a prototype and it is driving
  a real tool.
